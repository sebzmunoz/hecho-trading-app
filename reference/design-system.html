01 · Token architecture

Three tiers. One source of truth.

Every value the product renders resolves through three layers. A primitive is a raw fact. A semantic token is a role. A component token is a specific use. I move a brand or a theme by editing the layer that owns the decision, and nothing downstream needs to know.

Tier 1 · Primitive

Raw, theme-agnostic facts

The only place a literal hex, rgba, base px, or ms is allowed to live. Named by what they are, never by where they are used.

--brand-coral: #E94928; --green-500: #3A8A3A; --s-4: 16px; --r-3: 14px; --d-base: 300ms;
Tier 2 · Semantic

Roles, and theme-aware

What a value means. These flip between light and dark. Product components read these (or a component token), never a raw primitive.

--canvas: var(--brand-cream); --fg: var(--brand-ink); --action: var(--brand-coral); --positive: var(--green-700);
Tier 3 · Component

Specific, optional uses

A component may expose its own token that points at a semantic one, so a single component can be retuned in isolation.

--btn-bg: var(--action); --btn-fg: var(--on-action); --input-border: var(--line);

The token law

Every color in component CSS resolves to a token: no raw or URL-encoded hex, no rgba, no black/white keyword. Every layout spacing (padding, margin, gap), type size, motion duration, elevation, and z-index value resolves to its ladder; surface radius uses the radius ladder. The enumerated structural literals a component may use are: 0, hairline borders (--bw-1/--bw-2), 50%/100%, aspect-ratio, component-intrinsic geometry (control / icon / thumb / track / panel dimensions and the offsets that position them), small decorative-ornament radii, and transform offsets. The CI lint below enforces the color and spacing/type/duration rules. A stated law that is not enforceable is a defect, so the law is scoped to exactly what the lint can prove.

# lint.sh — fails the build on any raw value in component CSS
grep -niE '#[0-9a-f]{3,6}|%23[0-9a-f]{3,6}|rgba?\(|[^-a-z](black|white)[ ),;]' src/components/**/*.css   # raw + URL-encoded hex + keywords → must be empty
grep -nE '(padding|margin|gap|font-size|transition-duration|animation-duration):[^;]*[0-9]+(px|ms|s)' src/components/**/*.css \
  | grep -vE 'var\(|:0' # layout spacing / type / duration off-ladder → must be empty

Export & handoff

This is a working build, not a documented path. tokens/tokens.json (W3C Design Tokens) is the single source; node tokens/build-tokens.mjs (or npm run build:tokens) generates the committed outputs — build/web/tokens.css, build/ios/HechoTokens.swift, build/android[/night]/tokens.xml, build/figma/tokens.figma.json — and exits 1 if any token is missing on an applicable platform. A Style-Dictionary config (tokens/style-dictionary.config.js) is committed for teams that adopt SD. See §05 Verification for the real build transcript.

      "action":   { "$value": "{color.brand.coralDeep}", "$type": "color" },
      "canvas":   { "light": "{color.warm.200}", "dark": "{color.warm.900}" }

  },
  "space": { "4": { "$value": "16", "$type": "dimension" } },

# Build (committed, runs in CI):  npm run build:tokens  →  web · ios · android · figma  + parity gate (exit 1 on drift)
Parity rule. A token may not ship to one platform before the others. The Definition of Done requires the web, iOS, Android, and Figma outputs to be regenerated from the same tokens.json commit. A value that exists only in CSS is a defect.

02a · Color & theming

Five brand colors. One functional set. Two themes.

The five brand colors express Hecho and never change. State (positive, caution, critical, info) is carried by a separate, governed functional set that is never decorative. Pure black is never used; brand gray is the darkest ink. Every pairing below is measured, in light and dark.

Accessible brand shades (derived, no new hue)

Bright Terracotta measures 3.23:1 on Antique White, so as text it is reserved for large display (≥24px) and non-text accents — and, per Mandate 1, for the primary button fill, whose white label is large (19px/700) so its 3.54:1 clears AA-large. For small coral text, links, errors, and small buttons, the system uses Deep Terracotta (--coral-700 / --action-sm), a darker shade of the same hue that clears 4.5:1. On peach grounds, text is always ink.

Functional palette (governed; never decorative)

State cannot be read from a warm red-peach-gray palette without ambiguity, so the system adds two functional hues beyond the brand five — an accessible green for positive, and a distinct amber for caution so "low" is never mistaken for "critical" — while critical reuses the deep Terracotta and info stays neutral. Each role exposes a text value (AA), a pip/fill value, and a surface tint, in both themes. Color never carries meaning alone (see Accessibility · Color independence).

--criticalcoral-700 text · terracotta pip · error, blocked, overdue
--infoink-soft · neutral informational state, always with an icon

Dark theme

Dark is a first-class theme, not an inversion. Dynamic type, truncation & expansion

01Reader scaling

Sizes are rem; the root respects OS text size and zoom to 200% with no loss of content or function (WCAG 1.4.4). Clamp upper bounds are in rem, not px.

02Line length

Body and lead cap at 62ch. Below 48ch, reduce to one column. Never set body wider than 75ch.

03Truncation

Single-line truncation only on non-essential secondary text. The full value is always in the accessible name; price, quantity, and status never truncate.

04String expansion

Layouts hold a 1.35× expansion budget for translated strings. Buttons and labels wrap to two lines before they clip.

Primary-label minimum (Mandate 1 / Route A). The primary button fill is Fiery Terracotta #E94928, where white text is 3.54:1 — AA large-text only. So a primary .btn label is locked to --fs-primary-label-min = 19px, weight 700, no uppercase tracking (a real label, not a caps micro-string). Any control that needs a smaller label is not vivid red: .btn.sm uses the deep --action-sm fill where white clears 4.5:1. White-on-#E94928 below 18.66px/700 is a blocking defect.

Italic emphasis & descender safe-zone

Editorial italic emphasis sits in display and heading copy only, always in Terracotta at ≥24px. Body never uses italic for emphasis (use weight or color). Animated reveals clip type with overflow:hidden; every .split-mask lifts to line-height:1.18 with padding-bottom:0.12em so the tails of p, y, g, q, j survive.

02c · Spacing, grid & responsive

Eight-point rhythm. Real breakpoints.

Every padding, margin, gap, and dimension is a multiple of 4 (half step) or 8 (base). Touch-target sizes are a separate, named tier. The grid, breakpoints, safe areas, and orientation rules are specified, not left to "graceful".

Touch-target tier

Control heights are intentionally off the 8-grid because fingers are not: --control-sm 36, --control-md 44, --control-lg 52, with --hit-min 44 as the floor for any tappable element (48 for primary actions, achieved with padding when the visible shape is smaller).

Breakpoints & grid

Mobile · 4-column

Columns 4 · Gutter 16px · Margin 24px · 320–767px

Tablet · 8-column (graceful scale-up)

Columns 8 · Gutter 24px · content max 720px, centered · ≥768px. Same components, wider gutters, two-up lists. Nothing tablet-exclusive.
Concrete responsive rules (no "graceful"):
  • Small phone (320–359px): single column; reduce card padding to --s-3; tab labels persist; price/qty never wrap.
  • Default phone (360–429px): the reference frame, 380px content.
  • Large phone / foldable cover (430–767px): content caps at 430px, centered; one column.
  • Tablet (≥768px): 8-column grid, content max 720px; lists go two-up; sheets become centered dialogs ≤480px; the bottom tab bar stays bottom.
  • Safe areas: headers add env(safe-area-inset-top); the tab bar adds max(--s-3, env(safe-area-inset-bottom)); full-bleed media respects left/right insets in landscape.
  • Orientation: portrait-first. In landscape, the scan viewfinder keeps 4:5 centered with letterboxing; sheets cap at 80vh and scroll inside.
  • Reflow: all content reflows to a single column at 320px CSS width with no horizontal scroll (WCAG 1.4.10).

02e · Iconography

Line icons. One weight. Brand color.

One stylistic axis: a single 1.6px stroke on a 32px keyline grid (which reads as an optical 1.5 at the 24px display size), round caps, round joins, no fill. Icons inherit color via currentColor, never hard-coded.

01Stroke

Exactly 1.6px at the 32px viewBox. One weight only; mixed weights are rejected. (v1.0 shipped both 1.5 and 1.8 — now unified.)

02Grid

32px keyline box, 2px padding, shapes snap to the grid. Optical centering overrides geometric centering.

03Color & size

Always currentColor. Two sizes: --icon-md 20 inline, --icon-xl 48 standalone; 24 for tab bars.

04Fill & contribution

Outline only; the sole fill exception is a status pip. New icons ship with the grid file, both themes checked, and a name in the taxonomy below, or they are rejected.

Starter set (32, one stroke)

Naming taxonomy: action.* (scan, search, plus), object.* (cart, draft, order), nav.* (chevron-*, home), status.* (check, warning, info), system.* (settings, bell). New icons join an existing namespace.

02f · Illustration & photography

Line vignettes for us. Photography for the brands.

Illustration is the house voice for empty states and editorial. Product imagery is photography, supplied by brands to a fixed spec, with a deterministic fallback so a missing photo never breaks a layout.

Illustration

01Single stroke

1.5px, round caps and joins. No mixed weights.

02Single color

currentColor, typically Terracotta. No fills, shading, or gradients.

03Flat-lay groupings

2 to 4 observed objects in balance. Never one object alone.

04Observed, not invented

Real product shapes (vessels, plants, paper goods). Avoid abstract glyphs.

Product photography

Brands supply photography; Hecho enforces the spec. Imagery is warm and unfiltered: no heavy color grade, no drop shadows added in-app, no text baked in. The system never invents a photo, it falls back.

01Aspect ratios

Product 1:1; brand hero 3:2; style-guide vignette 4:5. Crop to fill, focal point centered, never distort.

02Treatment

True-to-product color; ≥1500px on the short edge; sRGB; subject on a warm-neutral or in-context ground. No filters, frames, or watermarks (privacy watermark is applied by the app, not baked in).

03Fallback chain

Photo → house line illustration (by category) → brand monogram on --surface-2. A layout never shows a broken or empty image well.

04Loading & a11y

Blur-up from a 24px LQIP; skeleton if none. Every image carries alt text: product name + brand; decorative grounds are aria-hidden.

Reduced motion — true and total

When the user prefers reduced motion, the CSS media query collapses every transition and animation to a cut, and the JS guards the cursor, magnetic button, header transform, and scroll smoothing behind a runtime check that re-evaluates if the setting changes mid-session. Reveals become immediate; the scan line, shimmer, and marquee freeze. No information ever depends on motion, and a shake never replaces a written error.

02h · Voice & content

One person, in plain English.

Hecho's voice is one maker speaking to one boutique buyer. First person singular. Editorial, restrained, warm. The product never says "we", never uses an em-dash, never names a specific date or clock time.

Principles

Use

"I'll keep your drafts open between visits. Pick up where you left off."

First person. Concrete benefit. Plain words. Speaks to one buyer.

Avoid

"We're excited to announce our new draft persistence feature, available 24/7."

Plural "we", marketing energy, an irrelevant time claim.

Use

"Scan a real shelf. Get stock, last order, and a reorder rec in one card."

Verb-first, specific. Sounds like an instruction, not a brag.

Avoid

"Leverage our AI-powered scanning platform to unlock data-driven insights."

Jargon. Removes the buyer from the sentence.

Use

"Your tax ID is due for renewal. Submit when you're ready."

Neutral, no urgency theater, gives control to the buyer.

Avoid

"ALERT: Tax ID expires in 14 days! Update now to avoid disruption!"

All-caps shouting, a specific count, fear language.

08 · Decisions

Every call is made. Here is why.

No open questions ship with this system. Each decision below is final and carries its rationale; revisit only through the contribution workflow with a new ADR.

ADR-01 · Primary button is Fiery Terracotta (Route A).
The vivid brand red carries the CTA. White-on-it is 3.54:1, so the label is locked to large text (19px/700, no caps); small buttons use the deep --action-sm fill (6.08:1). Brand vibrancy and AA both hold, proven by contrast.mjs.
ADR-02 · Functional palette adds two hues (green + amber).
Positive cannot be read from a warm red-peach-gray palette; amber keeps "low" distinct from "critical". Both are governed, never decorative, and contrast-audited; brand expression stays five colors.
ADR-03 · Toasts/offline bars are a fixed dark pill in both themes.
Status-text tokens lighten in dark and break as fills; a theme-invariant dark pill keeps the action/positive text AA in every theme.
ADR-04 · Dark-theme peach surface = #3A2A26.
A desaturated warm tint reads as "the peach band" on dark without glare; confirmed against the warm near-black canvas.
ADR-05 · Screenshot watermark is iOS-native, Android soft-overlay.
Only iOS exposes a screenshot interceptor; Android renders a "for buyer eyes" overlay. The privacy mask itself is identical on both.
ADR-06 · Reps co-shop but do not submit.
Submit authority stays with the buyer (P1) to honor "suggest, don't decide"; a future grant would add a permissions row in S407, not change the default.
ADR-07 · Tier-locked lines never show the dollar number.
A generic "Higher tier" hint plus a Request-access path (S804). Price exposure is gated server-side; the component cannot leak it.
ADR-08 · Camera ground is a documented palette exception.
A usable dark viewfinder cannot come from the five brand colors; --viewfinder-* are named, theme-invariant tokens, the one sanctioned exception.
ADR-09 · Tokens are generated, never hand-kept.
tokens.json is the source; web/iOS/Android/Figma are built by build-tokens.mjs with a parity gate. The inline :root matches the generated web output (checked by verify-counts.mjs).
ADR-10 · The law is scoped to what the lint can prove.
Colour and layout-spacing/type/duration are token-enforced; component-intrinsic geometry and transform offsets are enumerated structural literals. An unenforceable law is a defect, so the law equals the lint.

11 · Governance & versioning

What is safe to depend on, and what "done" means.

Consumers need to know a component's status, how it will change, and how to add one. Every component carries a lifecycle badge; tokens and components version on SemVer; contribution and deprecation are written rules.

Lifecycle status

Rendered on every component in this doc.

StableBetaDeprecated
  • Stable: production-ready, AA-audited, both themes, full state matrix. Breaking change needs a major bump + migration note.
  • Beta: usable, API may shift (e.g. sync-conflict resolver). No SLA on breaking changes within the minor line.
  • Deprecated: still works, scheduled for removal; ships with the replacement and a sunset version.

Versioning (SemVer)

  • Major: remove/rename a token or component, change a default that alters layout, drop a supported state.
  • Minor: add a token, component, variant, or state; non-breaking.
  • Patch: fix a value (e.g. a contrast correction), bug, or doc.
  • Tokens and components share the system version; tokens.json is tagged with it.

Contribution workflow

  • 1 · Propose in the system channel with the screen need + Brief reference.
  • 2 · Token-first: add/justify any new token in tokens.json; no raw values.
  • 3 · Build to the Definition of Done (right).
  • 4 · Review by a system maintainer + an accessibility reviewer.
  • 5 · Regenerate web/iOS/Android/Figma from one commit; merge; changelog entry.

Definition of Done

  • Full rendered state matrix (default → error).
  • Light + dark values supplied via semantic tokens.
  • Contrast logged for every text pairing, AA pass.
  • Accessibility test protocol passed and logged.
  • Zero raw/encoded hex, rgba, or color keyword in component CSS; layout spacing, type size, and motion duration resolve to tokens (the published lint is green).
  • Token added to the master table; exports regenerated on all platforms.
  • Anatomy, variants, usage-when, and do/don't documented.

Deprecation policy

A deprecated component is marked in the doc, emits a console warning in dev, and lists its replacement and the version it will be removed in. Minimum one major version of overlap. No silent removals.

Self-governance lint

CI runs the regex checks from Token architecture on every PR: no raw color in component CSS, no off-ladder dimension/duration. A stated law that is not enforced is a defect; this makes the law executable, not aspirational.
